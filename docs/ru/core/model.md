# Доменная модель (`core.model`)

[English](../../en/core/model.md)

Пакет описывает семантическую структуру API-документа и всех его составных частей.

## Структура документа

Корневым объектом является `ApiDocument`. Он объединяет:
- общую информацию об API (`ApiInfo`, `Contact`, `License`, `ExternalDocumentation`);
- список серверов и их переменных (`Server`, `ServerVariable`);
- список путей и HTTP-операций (`PathItem`, `Operation`, `HttpMethod`);
- переиспользуемые компоненты (`Components`);
- теги (`Tag`) и требования безопасности (`SecurityRequirement`, `SecurityScheme`, `OAuthFlows`, `OAuthFlow`);
- параметры, заголовки, тела запросов, медиа-типы и ответы (`Parameter`, `Header`, `RequestBody`, `MediaType`, `Encoding`, `Example`, `ApiResponse`).

## Идентификация и именованные элементы

Элементы, у которых должна сохраняться идентичность при редактировании (документ, пути, операции, параметры, схемы, свойства схем, компоненты и др.), реализуют интерфейс `IdentifiedElement` и хранят `ElementId`.

В тех местах, где в спецификации элементы записываются как пары «имя → определение» и могут переименовываться, вместо `Map` используются упорядоченные списки обёрток с собственным идентификатором:
- пути в документе хранятся как список `PathItem` (у каждого свой идентификатор и строковый путь);
- схемы в компонентах хранятся как список `SchemaComponent`;
- свойства внутри схемы хранятся как список `SchemaProperty`;
- остальные секции компонентов (`parameters`, `responses`, `requestBodies`, `headers`, `securitySchemes`, `examples`) хранятся как списки `NamedComponent`.

Это позволяет сохранять исходный порядок элементов и менять их имена без потери внутреннего идентификатора.

## Модель схем (`core.model.schema`)

Схема представлена закрытым интерфейсом `Schema` с двумя реализациями:
- `BooleanSchema` — булева схема (`true` или `false`), используемая, например, в `additionalProperties` или `items`;
- `SchemaObject` — единая композиционная модель объекта схемы.

Схема не делится на жёсткую иерархию примитивов, массивов и объектов. Один экземпляр `SchemaObject` может одновременно сочетать набор типов (`Set<JsonType>`), свойства объекта (`properties`, `required`, `additionalProperties`), описание элементов массива (`items`), числовые и строковые ограничения, композицию (`allOf`, `oneOf`, `anyOf`, `not`), `Discriminator` и ссылку на другую схему (`SchemaReference`).

Обязательность свойств хранится в схеме отдельно от списка самих свойств (`Set<String> required`), поэтому схема может объявлять обязательными поля, которые ещё не добавлены в `properties` или наследуются через композицию.

`JsonType.NULL` представляет тип JSON null. В модели `nullable: true` из OpenAPI 3.0 объединяется с объявленным типом, а объединение типов из OpenAPI 3.1 представлено несколькими значениями `JsonType`. `SchemaObject.builder(existingSchema)` начинает с глубокой копии, поэтому изменение одного поля сохраняет остальные значения и идентификаторы вложенных элементов.

## Встроенные объекты и ссылки (`core.model.reference`)

В отличие от схем, где `$ref` может соседствовать с другими ключевыми словами внутри одного объекта, остальные элементы спецификации (параметры, тела запросов, ответы, заголовки, примеры, схемы безопасности) могут быть либо встроенным объектом, либо ссылкой.

Для них используется закрытый интерфейс `ReferenceOr<T>`:
- `InlineObject<T>` — содержит сам встроенный объект;
- `ObjectReference<T>` — содержит идентификатор ссылки, строку `$ref`, а также необязательные переопределения `summary` и `description`.

## Значения данных (`core.model.value`)

Произвольные данные внутри документа (значения `default`, `example`, `examples`, `enum`, `const`) описываются закрытым интерфейсом `DocumentValue` и его реализациями: `NullValue`, `BooleanValue`, `NumberValue`, `StringValue`, `ArrayValue`, `ObjectValue`.

Такое представление позволяет:
- явно отличать отсутствие поля в документе (Java `null`) от явно заданного пустого значения (`new NullValue()`);
- не смешивать пользовательские данные примеров с настоящими узлами и `$ref`-ссылками самого документа.

## Переопределение безопасности в операции

В OpenAPI отсутствие поля `security` у операции означает наследование глобальных правил документа, а пустой список `security: []` отключает авторизацию для конкретной операции.

Чтобы различать эти два состояния, `Operation` хранит флаг `hasSecurityOverride()`:
- при вызове `builder.security(...)` (в том числе с пустым списком) флаг устанавливается в `true`;
- по умолчанию (или после вызова `builder.inheritSecurity()`) флаг равен `false`, и операция наследует правила уровня документа.

# Навигация и ссылки (`core.navigation`, `core.reference`)

[English](../../en/core/references.md)

Эти два пакета отвечают за адресацию узлов документа по стандарту JSON Pointer (RFC 6901), индексацию элементов по путям и идентификаторам, а также за разрешение и учёт локальных `$ref`-ссылок.

## Адресация узлов (`DocumentPath`)

`DocumentPath` представляет путь к узлу документа в виде неизменяемого списка неэкранированных строковых сегментов и поддерживает два формата записи:
- **JSON Pointer** (`parse("/paths/~1users/get")` и `toString()`) — экранирует только символы `~` (`~0`) и `/` (`~1`);
- **URI-фрагмент** (`fromFragment("#/components/schemas/User")` и `toFragment()`) — дополнительно выполняет UTF-8 percent-encoding/decoding для спецсимволов URI (пробелы, `%`, `#`, `+`, не-ASCII символы).

Для проверки вложенности путей используется метод `startsWith(prefix)`, который сравнивает пути целиком по сегментам, а не по текстовому префиксу (поэтому `/components/schemas/User2` не считается подпутём `/components/schemas/User`).

## Индекс документа (`DocumentIndex`)

`DocumentIndex.build(document)` проходит по дереву документа и строит быстрый индекс для поиска элементов:
- `findById(id)` — находит элемент и его логический путь по внутреннему `ElementId`;
- `findByPath(path)` — находит целевой объект по его `DocumentPath`.

Особенности сопоставления путей:
- пути формируются по правилам структуры OpenAPI, а не по именам внутренних Java-полей (например, операция `GET` внутри пути `/users` имеет адрес `/paths/~1users/get`, без промежуточного сегмента `operations`);
- обёртки именованных элементов (`SchemaComponent`, `SchemaProperty`, `NamedComponent`, `InlineObject`) прозрачны для путей и делят один и тот же `DocumentPath` со своим вложенным объектом;
- при поиске `findById` можно получить как саму обёртку (по её ID), так и вложенный объект (по его ID), и у обоих будет один и тот же `DocumentPath`;
- при поиске `findByPath` возвращается конечный целевой объект (например, `Schema` или `Parameter`), на который указывают ссылки `$ref`.

## Разрешение ссылок (`ReferenceResolver`)

Резолвер принимает индекс документа, строку ссылки и ожидаемый тип целевого объекта, возвращая результат `ReferenceResolution<T>`:
- `ResolvedReference<T>` — содержит найденный типизированный объект, конечный путь `targetPath` и список всех пройденных узлов `traversedPaths`;
- `UnresolvedReference<T>` — содержит причину неудачи (`ReferenceFailure`) и список узлов `traversedPaths`, которые удалось пройти до ошибки.

Если ссылка указывает на компонент-алиас (например, параметр в `components/parameters`, который сам является ссылкой на другой параметр), резолвер проходит по всей цепочке до конечного объекта и записывает все промежуточные пути в `traversedPaths`. Схема, ссылающаяся сама на себя (`$ref` внутри `SchemaObject`), возвращается сразу как целевая схема без бесконечного разворачивания.

Причины неразрешённых ссылок (`ReferenceFailure`):
- `INVALID_REFERENCE` — синтаксически некорректный URI, невалидный percent-escape или неправильная последовательность `~` в JSON Pointer;
- `EXTERNAL_REFERENCE` — ссылка содержит схему (`http`/`https`), хост, query или путь к внешнему файлу;
- `UNSUPPORTED_ANCHOR` — фрагмент не начинается с `/` (например, JSON Schema якорь `#User` вместо JSON Pointer `#/components/schemas/User`);
- `TARGET_NOT_FOUND` — по указанному пути в документе нет узла;
- `TYPE_MISMATCH` — узел найден, но его тип не соответствует ожидаемому в месте использования ссылки;
- `CYCLIC_REFERENCE` — цепочка компонентов-алиасов замкнулась в цикл.

## Индекс использований ссылок (`ReferenceIndex`)

`ReferenceIndexBuilder.build(documentIndex)` собирает все места использования ссылок в документе в единый `ReferenceIndex`:
- ссылки на схемы (`ReferenceKind.SCHEMA`) — поле `$ref` внутри `SchemaObject`;
- ссылки на объекты (`ReferenceKind.OBJECT`) — экземпляры `ObjectReference` в параметрах, телах запросов, ответах, заголовках, примерах и компонентах;
- сопоставления дискриминатора (`ReferenceKind.DISCRIMINATOR_MAPPING`) — записи в `Discriminator.mapping`, где поддерживаются как полные ссылки `#/components/schemas/...`, так и короткие имена существующих схем.

Данные `DocumentValue` (в полях схемы `default`, `enum`, `const`, `example` и `examples`, а также внутри значений расширений `x-*`) не индексируются как ссылки, даже если содержат ключ `"$ref"`.

Основные возможности `ReferenceIndex`:
- `usages()` и `unresolvedUsages()` — все ссылки документа и список неразрешённых ссылок;
- `findBySource(path)` — поиск ссылки по адресу самого поля `$ref` (или записи `mapping`);
- `referencesTo(id)` и `referencesTo(path)` — все входящие ссылки, которые ведут к указанному элементу (включая ссылки, проходящие через него транзитивно по цепочке алиасов);
- `referencesToSubtree(path)` и `referencesFromSubtree(path)` — все входящие ссылки в поддерево и все исходящие ссылки из поддерева.

# Позиции ссылок при редактировании схем

[English](../../en/openapi/references.md)

Переименование и удаление компонентов/свойств схем используют общую классификацию ссылок исходника. Она рекурсивно следует ролям объектов, а не сопоставляет пути фиксированной глубины:

- Schema Object в `components.schemas`, `schema` параметров/заголовков и `schema` Media Type; вложенные карты схем (`properties`, `patternProperties`, `dependentSchemas`, `$defs`, `definitions`), поля с одной схемой (включая `items`, `additionalProperties`, `contains`, `if`/`then`/`else`, `unevaluatedItems`, `unevaluatedProperties`, `contentSchema`) и массивы схем (`allOf`, `anyOf`, `oneOf`, `prefixItems`). Значения discriminator mapping также переносятся.
- Path Item в `paths`, `webhooks` и `components.pathItems` OAS 3.1, а также в выражениях callback внутри callbacks операций и `components.callbacks`. Вложенность callbacks может повторяться на любой глубине. Параметры пути/операции, тела запросов и ответы обрабатываются одинаково во всех Path Item.
- Media Type в content тел запросов/ответов и content параметров/заголовков. Заголовки encoding рекурсивно используют те же роли Header и Media Type, включая вложенные `encoding.*.headers`.
- Reference Object в переиспользуемых параметрах, заголовках, телах запросов, ответах, callbacks, examples, links, security schemes и path items; во встроенных позициях параметров, заголовков, тел запросов, ответов, callbacks, examples и links; поле `$ref` Path Item. Классификация определяет позиции полей ссылок, но не проверяет соответствие типа цели требуемому типу объекта OpenAPI.

Каждый `$ref` исходника относится к распознанной позиции, непрозрачному значению (литерал или payload расширения) либо нераспознанной позиции. Литеральные ключевые слова схем, примеры параметров/Media Type, `value` Example Object, значения параметров/request-body Link Object и payload `x-*` непрозрачны. Имена элементов карт, например свойства или заголовка `x-name` или `example`, а также метки discriminator mapping, включая `$ref`, остаются именами, а не полями литералов/расширений. Расширения объекта `paths` также непрозрачны.

Распознанный локальный указатель на переименовываемый компонент/свойство или его потомков переносится. Нераспознанный `$ref` на это поддерево вызывает отказ rename через `Refused(UNRECOGNIZED_REFERENCE)` с перечнем всех нераспознанных позиций. Delete возвращает `Rejected` с `EditRejected(REFERENCED_TARGET)` с перечнем всех входящих распознанных и нераспознанных позиций вне удаляемого поддерева, включая отсутствующие в семантической модели. Посторонние, внешние и непрозрачные значения не меняются. Отказ сохраняет исходную модель и байты; частичная правка не публикуется. Эти правила не добавляют разрешение внешних ссылок и не снимают существующее ограничение областей `$id` OAS 3.1.

Версионные YAML/JSON-каталоги `reference-locations-3.0.*` и `reference-locations-3.1.*` в тестовых ресурсах модуля, их списки позиций и ожидаемые документы после rename служат переиспользуемой переписью этих ролей ссылок.

Варианты результата и атомарность описаны в [контракте редактирования](editing.md).

# OpenAPI import

[Русский](../../ru/openapi/import.md)

Call `OpenApiImporter.importDocument(bytes, options)`, using `ImportOptions.autoDetect()` or an explicit `withFormat(...)` hint. The importer retains the original bytes, checks UTF-8 and syntax, detects duplicate keys, and accepts OpenAPI 3.0.x and 3.1.x. Scalar inputs can require an explicit format. `ImportResult` exposes the status, diagnostics, detected format and version when available, and an optional document. `IMPORTED` means a model was produced; parser diagnostics can still be present and do not imply full OpenAPI validation. An unsuccessful import retains the source but has no editable model. Returned source bytes and model snapshots are defensive copies.

The current mapping covers selected `info` fields and schema components, including supported nested schema fields and values. It does not yet map paths, operations or all other OpenAPI objects. Source preservation does not mean these sections are represented in `core` or validated completely. External references are not resolved or fetched. Some inputs, including schemas the underlying parser fails to interpret, are rejected with a mapping diagnostic.

Schema `default`, `example`, `examples`, `enum` and `const` values retain the decimal precision of JSON and YAML numbers, including numbers nested in arrays and objects. The six integer constraints `minProperties`, `maxProperties`, `minItems`, `maxItems`, `minLength` and `maxLength` are read from the source as `BigInteger`, so values above `Integer.MAX_VALUE` are retained in the model after import and editing. This does not add validation of negative or non-integer constraint values; the underlying parser's existing handling still applies to values that are not decimal integers.

## Source size and offline import

`ImportOptions.maxSourceBytes()` sets the source budget in bytes, including a UTF-8 BOM and whitespace. The default and supported maximum are **3,145,728 bytes (3 MiB)**, matching the underlying Swagger YAML parser's ceiling conservatively for UTF-8 input. Use `ImportOptions.autoDetect().withMaxSourceBytes(limit)` or `ImportOptions.withFormat(format).withMaxSourceBytes(limit)` for a smaller budget. Values outside `1..ImportOptions.MAX_SUPPORTED_SOURCE_BYTES` are caller errors (`IllegalArgumentException`). The one-argument `ImportOptions(Optional<SourceFormat>)` constructor keeps the default budget.

The importer checks the budget before UTF-8 decoding, format detection or parsing, for both YAML and JSON. A source exactly at the limit is allowed; a larger source returns `SOURCE_TOO_LARGE` with a diagnostic containing the actual and allowed byte counts. It retains the original bytes and explicit format hint, if any, but has no version, model or diagnostic location. An oversized malformed source also returns this status, rather than an encoding or syntax error. The caller that reads a file or HTTP response must separately limit buffering; this byte-array API already receives the complete content. The limit applies to import admission; it is not a per-document editing quota. Editing re-imports with the default budget.

Import interprets only the supplied bytes. Swagger Parser is called with `resolve=false` and external-reference validation disabled: HTTP/HTTPS and relative file `$ref` values remain references, without network requests, file reads or classpath-resource lookups for those targets. Resource loading belongs to the caller (eventually `server`). SnakeYAML settings and the Jackson mapper are shared by import and source editing; global Swagger Parser settings are not changed.
